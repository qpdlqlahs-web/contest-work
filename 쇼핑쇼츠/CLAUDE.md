Claude는 요청받은 것만 처리하고 넘기지 말고, 숏폼 커머스 전문가의 시선으로 결과물을 직접 검수하며 일한다.

- 직접 촬영 없음. 상품 사진은 **판매자가 허락한 것만** 쓴다 (시트 `사진 허락` = O, `허락 근거` 기록).
- 남의 영상(해외 쇼츠, 틱톡·도우인 영상 등)을 가져다 쓰지 않는다. AI로 상품 기능 시연 장면을 만들지 않는다.
- 광고 표시: 영상 첫·마지막 화면 문구(자동), 설명란 제휴 문구(자동 생성), 유튜브 업로드 시 '유료 프로모션 포함' 체크.
- 쇼핑커넥트 대가성 문구는 토씨 그대로: "이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다."
  유튜브: 롱폼 = 설명란 첫 줄(더보기 없이 보이게), **쇼츠 = 고정 댓글 맨 위**. 여기에 제목[광고]·영상 내 자막·유료 광고 배너 중 1개 이상 추가.
  클립: 쇼핑커넥트 태그를 달면 본문 맨 앞 [광고] 자동 표시(안 붙으면 직접), **첫 번째 댓글로 대가성 문구 고정**. 네이버TV는 제목에 [광고].
  문구를 바꾸거나 해시태그 사이에 숨기면 위반.
- 브랜드커넥트 통계 지표(조회수·클릭 수 등)와 정산 실적(수익 금액)은 어디에도 공개 금지 (영상·SNS·블로그·판매자 메시지 포함).
  판매자에게는 숫자 없이 영상 링크만 보낸다.
- 체험·후기처럼 들리는 표현 금지 ("써보니", "받고 울었어요" 등). 실제로 써본 게 아니면 표시광고법 문제.
- 피할 주제: 교사 대상 선물(청탁금지법), 건강 효능 표현(건강기능식품·의약품 광고 규정), 주류.
- `고른 이유` 한 줄은 영수 님이 직접 쓴다. Claude는 초안을 제안할 수는 있지만 확정은 영수 님 몫.
  이 한 줄이 큐레이션의 가치이고, 링크만 반복하는 스팸 채널로 분류되지 않게 해 주는 장치다.

## 숫자형 (사진 없는 리뷰·평점 비교) — 2026-10-03 추가
- 브랜드커넥트 약관 제9조③2·운영정책 2-1)상 판매자 사진은 허락 없이 못 쓴다. 대신 **사실 정보(상품명·가격·리뷰 수·평점)만으로** 만드는 형식.
- `영상` 시트 `형식` = `숫자` → 사진·사진 허락 검사 생략, `상품` 시트 `리뷰 수`·`평점` 필수. 비우면 기존 사진형.
- 숫자는 상품 페이지 표시값 그대로 옮기고, 확인한 날짜를 `가격 확인일`에 적는다 (영상·설명란에 기준일로 나감).
- 금지: 리뷰 문장 인용(저작권·추천보증 지침), 브랜드 로고, 실제 상품처럼 보이는 AI 이미지.
- 어필리에이트 약관(2026.08) 제8조: 숫자는 공개 상품 페이지 값만 쓰고 수수료율·대시보드 정보는 영상에 넣지 않는다(5호),
  다른 회사 브랜드명 언급 금지(20호), 본인·가족 구매 금지(16호). 제5조: 상품 진행 상태가 월 중에도 바뀌니 업로드 직전 확인.
- 클립에서는 쇼핑커넥트 스티커가 실제 상품 사진을 띄워 준다. 사진 허락을 받은 상품은 나중에 사진형으로 다시 만들어도 된다.
- 훅 줄바꿈이 어색하면 엑셀 셀 안에서 Alt+Enter로 직접 끊는다. 샘플: `DEMO2`.
- 숫자형은 모션그래픽으로 렌더링한다: 시트 `순서`와 상관없이 리뷰 수 순위로 정렬해 3위→1위로 공개,
  숫자 카운트업·막대·카드 등장. 광고 표시는 첫 프레임부터 고정. 한 편 제작 약 30초.

## 콘텐츠 공식
- 제목: **상황 + 예산 + 대상** (예: "집들이 선물 3만 원대, 휴지 말고 이거"). 선물 사는 사람은 예산부터 정한다.
- 구성 약 21초: 훅 2.5초 → 상품 3개 × 5초 (이름 · 고른 이유 · 가격) → 정리 + 구매 안내 3.5초.
- 훅 문구 20자 안팎. 그 상황의 고민을 찌르는 말 (예: "집들이 선물, 아직도 휴지 사세요?").
- 상품 고르는 기준: 리뷰 많고 평점 높음, '선물하기'(주소 몰라도 보내기) 지원, 품절 위험 낮음, 가격이 예산 안.
  - (2026-10-10 추가) 그 상품이 푸는 '검색하는 고민'을 한 줄로 적는다(예: 장모님 생신 선물, 신혼집 집들이). 훅에 그 상황을 넣는다. 추천은 구독자가 아니라 그 고민을 가진 시청자에게 닿는다(위키 playbooks/youtube-pull-strategy.md).
- 같은 상품을 여러 주제에 다시 써도 된다 (사진 허락 받는 부담을 줄이는 방법).

## 한 편 작업 흐름
1. `영상` 시트에서 주제 확정 → 상태 `상품선정`.
2. 쇼핑커넥트에서 상품 3개 선정 → `상품` 시트 입력 → 판매자에게 사진 허락 요청
   (`templates/seller_permission_request.md`) → 상태 `허락대기`, `판매자` 시트에 기록.
3. 허락받은 사진을 `assets/products/`에 저장 (파일명은 영문·숫자 권장, 예: `v01_1.jpg`) → `사진 허락` = O, 허락 근거 기록.
4. `링크 번호` 지정 (영상마다 겹치지 않게) → 상태 `제작대기` → `--check` → `--ready`.
5. Claude 검수(아래) → 업로드 → 상태 `업로드완료`.
6. 1주 뒤 `성과` 시트 기록 (영상·플랫폼마다 한 줄, 최신 누적값으로 덮어쓰기)

## Claude 검수 기준 (영상을 만들 때마다 반드시)
- `output/<ID>/<ID>_preview.png`를 직접 열어 본다. 빨간 영역 = 앱 UI가 가리는 곳.
  - 글자나 상품이 빨간 영역에 걸리지 않는가
  - 한 단어만 덩그러니 남는 줄, 잘린 글자(…)가 없는가
  - 상품명·가격이 시트와 같고, 첫·마지막 화면에 광고 표시가 있는가
  - (숫자형) 리뷰 수·평점·기준일이 시트와 같고, 순위 막대가 리뷰 수 순서와 맞는가
  - 훅이 0.5초 안에 읽히는 길이인가, 3개 상품이 한눈에 비교되는가
- 스크립트가 출력한 `참고:` 경고를 모두 읽고, 고칠지 영수 님에게 묻는다.
- 필요하면 ffmpeg로 프레임을 뽑아 실제 영상도 확인한다 (예: `ffmpeg -ss 7 -i 파일.mp4 -frames:v 1 check.png`).
- 결과가 기준에 못 미치면 "완료"라고 보고하지 말고 문제와 개선안을 먼저 말한다.
